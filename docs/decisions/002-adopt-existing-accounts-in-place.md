# ADR-002: 原地纳管已有 Linux 账号

## 状态

Accepted

## 日期

2026-07-17

## 背景

物理机上已经存在管理员手工创建的团队账号。这些账号可能使用不同 home、UID、组和目录结构。现有授权角色只接受平台创建的数据盘目录和 `/home` 软链接，因此无法在不破坏现有数据的前提下管理旧账号。管理员还要求在确认前看到将执行的命令。

## 决策

将旧账号作为 `HostAccessGrant.account_origin = adopted` 原地纳管。纳管不迁移 home、不修改 UID、组、shell 或 sudo，只向原 `authorized_keys` 追加成员启用公钥。授权记录保存平台成功追加的完整公钥，以便撤销时精确删除这些行并锁定账号。平台创建的账号继续使用现有数据盘软链接和受控删除语义。

预检快照保存固定 Ansible 任务对应的等价 POSIX Shell 命令，前端必须展示命令并要求管理员显式勾选审阅后才能执行。实际执行仍使用 Ansible 模块，不把预览文本传给 shell。

## 备选方案

纳管时自动迁移 home 到数据盘：能统一目录结构，但可能影响运行进程、权限、挂载和大目录复制，失败回滚成本高，因此拒绝。

保留独立的旧账号运维页：实现较快，但成员、公钥和机器授权仍分散在两套模型中，无法可靠追踪平台添加的密钥，因此拒绝。

每次临时盘点而不保存授权关系：无需迁移数据库，但无法证明某把密钥是否由平台添加，也无法安全撤销，因此拒绝。

## 后果

授权角色必须维护创建与纳管两条明确分支，不能让纳管分支继承创建账号的组、sudo 或目录变更。撤销纳管账号会锁定整个账号，因此即使保留其他旧密钥也无法登录；界面必须在确认前提示这一点。旧账号迁移到数据盘需要未来独立设计，不能悄悄并入纳管流程。

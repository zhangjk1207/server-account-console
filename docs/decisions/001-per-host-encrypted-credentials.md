# ADR-001: 每台主机使用独立加密连接凭证

## 状态

Accepted

## 日期

2026-07-14

## 背景

控制台需要管理十余台物理机，但它们不一定共享同一 SSH 私钥或 sudo 密码。管理员需要先验证一台机器的 SSH 与 sudo，再选择是否对它运行账户、公钥和 SSH 配置操作。全局控制私钥会扩大泄露影响范围，也无法表达不同机器的 sudo 权限。

## 决策

每台主机保存一份可替换的 SSH 私钥和 sudo 密码。私钥通过文件上传，服务端仅接受无口令的 OpenSSH/PEM 格式；两个字段使用部署环境提供的 Fernet `CREDENTIAL_ENCRYPTION_KEY` 加密后写入 SQLite。任务运行期间才将私钥写为 `0600` 临时文件；Ansible Runner 的 inventory、extra vars、事件和进程环境也只存在于同一临时目录，任务结束后整体删除。数据库仅保留已脱敏的任务事件。

主机必须通过指纹确认、SSH 登录和 `sudo -S -k` 验证后，才能同步账户或执行用户/SSH 运维。周期探测复用该主机凭证。秘密不出现在 API 响应、任务快照、事件或日志中。

## 备选方案

全局 SSH 私钥：初始配置简单，但所有主机共享高价值秘密，无法覆盖不同 sudo 密码，也会让单机撤权变得困难。

将明文凭证放入 SQLite：实现最少，但数据库备份、文件读取或调试输出即可泄露秘密，不可接受。

完全依赖外部密钥管理系统：安全性更高，但对单管理员内网工具增加了部署依赖；保留未来集成空间。

## 后果

`CREDENTIAL_ENCRYPTION_KEY` 是必须备份的运行密钥；丢失它会使历史凭证无法解密，需要逐台重新上传。当前不支持带口令私钥，管理员应创建一个权限最小化的专用密钥。凭证更新后必须重新验证，所有变更任务继续保留预检与人工确认。

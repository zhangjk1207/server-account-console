# 成员中心的批量账号开通设计

**状态：** 已确认，待规格审阅
**日期：** 2026-07-16
**作者与审阅人：** jkzhang

## 1. 问题

当前控制台偏向逐台主机的通用 Linux 运维，不能高效表达团队成员在不同物理机上的不同账号、密钥和权限。模型训练团队还必须避免用户将模型和缓存写到系统盘。

## 2. 目标与边界

目标：

- 以成员为入口保存多个 SSH 公钥，并一次勾选多台机器开通账号。
- 每台机器可设置不同用户名、权限模板和数据盘目录。
- 每台机器配置自己的数据根目录；开通时创建 `{data_root}/{username}`，将 `/home/{username}` 指向该目录。
- 所有目标账户仅允许 SSH 公钥登录；批量开通和删除均经过预检和确认。
- 删除时逐机器勾选是否删除该机器的数据目录。

非目标：

- 不提供任意远程 Shell 或任意脚本输入。
- 不在首次重构中做配额、LDAP/AD、容器编排或多管理员审批。

## 3. 设计

### 3.1 领域模型

保留 `ManagedUser` 作为成员档案，保存显示名、默认用户名和多个启用的 SSH 公钥。

扩展 `Host` 的基础设施配置：

- `data_root`：该机器的数据根目录，必须为绝对路径。
- `home_link_root`：固定为 `/home`；创建结果为 `/home/{username}` -> `{data_root}/{username}`。
- SSH 密码登录策略默认关闭；连接继续使用每台机器独立的管理私钥和 sudo 密码。

新增全局 `PermissionTemplate`：名称、附加组、可选 sudo 规则。预置模板为“仅密钥登录”“Docker 训练”“管理员”，管理员可新增或修改模板。

新增 `HostAccessGrant`：成员、机器、该机器用户名、模板快照/覆盖组/覆盖 sudo 规则、计算后的数据目录、状态和最近成功任务。一个成员在一台机器上最多一个有效授权。

### 3.2 主工作流

默认页改为“成员与开通”。选择或创建成员后，进入批量开通工作台：

1. 表格列出所有可连接机器。
2. 每行独立勾选，填写或覆盖用户名，选择权限模板，必要时覆盖组和 sudo 规则。
3. 页面显示该行的机器数据根目录和最终目录；不允许编辑计算结果以外的危险路径。
4. 预检生成不可变快照，逐机检查指纹、SSH、sudo、目录冲突、现有账号和软链接目标。
5. 确认后在每台目标机创建目录、账户、公钥和 `/home/{username}` 软链接。

删除复用授权表：勾选授权记录后预检删除账户和 `/home/{username}` 链接；每行另有“删除数据目录”复选框，默认关闭。

### 3.3 页面结构

- 成员与开通：成员列表、公钥管理、批量开通/删除工作台，是日常入口。
- 机器：连接凭证、数据根目录、连接状态和低频诊断，不放日常用户盘点表。
- 权限模板：管理模板及其组、sudo 规则。
- 执行记录：按批次显示预检、确认、逐机结果与错误。

批量工作台以紧凑的机器表为核心，列为“选择、机器、用户名、权限模板、实际数据目录、预检结果”。组和 sudo 覆盖收在行内展开区，不占用默认视图。页面状态使用“未检测”而不是将用户锁定状态误显示为“等待中”。

### 3.4 远程操作与安全

固定 Ansible 角色执行以下顺序：验证数据根目录安全性，创建数据目录，创建账户但不创建默认家目录，将账户的逻辑家目录设为 `/home/{username}`，创建该路径到计算数据目录的受控软链接，安装启用的公钥，应用权限模板。

删除只允许处理与 `HostAccessGrant` 记录完全匹配的账户、`/home/{username}` 链接和 `{data_root}/{username}`。预检发现现有家目录不是受控软链接、数据目录不在配置根目录下、或账户与记录不匹配时必须失败，不能猜测或递归删除。

永不设置目标用户密码。SSH 密码登录继续由机器策略管理，默认关闭；管理连接凭证和运行期 Ansible 数据保持现有的加密和临时目录约束。

### 3.5 API 与任务

- `GET/POST/PATCH /api/permission-templates`
- `GET/POST /api/users/{user_id}/access-grants/preview`
- `POST /api/access-grant-jobs/{job_id}/execute`
- `GET /api/users/{user_id}/access-grants`

批量预检请求包含每台机器的 `host_id`、`username`、`permission_template_id` 和可选覆盖值。任务快照保存已计算的数据目录和删除选项，不保存秘密。

## 4. 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 成员中心批量开通 | 贴合管理员每天的工作流；可一次处理多机器差异 | 需要新增授权记录和批量表 | 采用 |
| 机器中心逐台维护 | 数据模型简单 | 十几台机器重复操作，无法高效开通 | 不采用 |
| 权限矩阵直接编辑 | 适合只读查看覆盖面 | 不适合填写用户名、数据目录和确认高风险删除 | 作为后续只读视图，不作为主流程 |

## 5. 测试与发布

- 单元测试：目录计算、路径逃逸拒绝、模板覆盖、删除边界和授权唯一性。
- 角色测试：创建账户、公钥、软链接；保留数据删除；删除数据目录；非受控家目录拒绝。
- API 测试：批量机器输入、逐行用户名、预检快照、确认门禁和错误返回。
- 前端测试：成员到批量开通的主流程、每行覆盖、删除数据复选框和异步反馈。
- 发布时保留原主机用户运维接口一版，但从默认导航移除；完成真实机器验证后再决定是否下线。

## 6. 已确认决策

- 每台机器只有一个管理员配置的数据根目录。
- `/home/{username}` 始终软链接到该机器计算出的数据目录。
- 删除数据目录必须逐机器显式勾选，默认不删除。
- 权限模板全局复用，但允许逐机器覆盖附加组和 sudo 规则。

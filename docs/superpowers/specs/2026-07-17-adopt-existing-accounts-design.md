# 已有 Linux 账号原地纳管与命令确认设计

**状态：** 已确认
**日期：** 2026-07-17
**作者与审阅人：** jkzhang

## 1. 问题

成员中心目前只能安全管理由平台新建、且 `/home/{username}` 是数据盘软链接的账号。服务器上由管理员过去手工创建的账号只能被盘点，无法关联成员、追加平台公钥或按同一工作流撤销权限。同时，预检完成后界面只显示“等待确认”，没有把即将发生的远程变更和等价命令放在确认按钮旁边，管理员无法审阅后再确认。

## 2. 已确认行为

- 已有账号采用“原地纳管”：保留 UID、主组、附加组、shell、home 和现有数据，不自动迁移到机器数据盘。
- 首次和后续开通只追加成员当前启用的 SSH 公钥，不覆盖或清理原有公钥。
- 平台记录自己追加到该账号的完整公钥及指纹。
- 撤销旧账号权限时，只移除平台记录的公钥，然后锁定账号；不删除账号、home 或任何数据。
- 再次开通时解锁账号并补回缺失的平台公钥。
- 同一机器上的同一用户名只能归属一个成员的有效授权。
- 旧账号迁移到数据盘不属于本次范围，未来作为独立高风险任务实现。

## 3. 数据模型

扩展 `HostAccessGrant`：

- `account_origin`: `created` 或 `adopted`。
- `remote_uid`: 纳管时盘点的 UID，平台新建账号可为空。
- `remote_primary_group`: 纳管时盘点的主组。
- `remote_home`: 纳管时盘点的原 home；平台新建账号为 `/home/{username}`。
- `managed_public_keys`: 平台成功安装到该授权的完整公钥集合。指纹由公钥解析得到。
- `data_directory`: 对 `adopted` 授权可为空；旧账号不要求机器配置数据根目录。

历史授权迁移为 `created`，继续遵守受控数据目录和软链接回收规则。

## 4. API 与不可变快照

`GET /api/hosts/{host_id}/users` 继续作为权威盘点接口。成员开通表在某行选择“纳管已有账号”后加载该机器用户，管理员从列表选择账号。开通请求增加：

```json
{
  "host_id": "host-id",
  "username": "alice",
  "account_origin": "adopted",
  "existing_account": {
    "uid": 1001,
    "primary_group": "alice",
    "home": "/home/alice"
  }
}
```

服务端验证用户名和绝对 home 路径，预检与正式执行时由 Ansible 重新读取 passwd 记录并断言 username、UID、主组和 home 仍与快照一致。任何变化都使任务失败并要求重新盘点、预检。

每个授权快照保存 `command_preview`，内容为该固定 Ansible 角色对应的等价 Shell 命令。所有参数使用 POSIX shell quoting。预览是审计信息，不通过 shell 执行；实际执行仍使用幂等 Ansible 模块。API 不返回管理私钥、sudo 密码或其他连接秘密。

## 5. 远程执行

### 5.1 原地开通

固定角色先读取 passwd 并验证账号快照，随后：

1. 保持账号 UID、组、shell、home 不变。
2. 解锁账号。
3. 在原 home 下确保 `.ssh` 和 `authorized_keys` 权限正确。
4. 使用追加语义安装成员启用公钥；已有同一公钥时保持幂等。

纳管模式忽略权限模板、组和 sudo 覆盖，避免“纳管”暗中改变旧账号权限。

### 5.2 原地撤销

固定角色重新验证 passwd 快照，逐一移除 `managed_public_keys` 中记录的公钥，然后锁定账号。其他公钥和 home 保持不变。即使检测到其他公钥，预检仍可完成，但命令预览显示“锁定后所有密钥均无法登录”的警告。

### 5.3 平台创建账号

保持现有创建、数据目录、home 软链接、权限模板和受控回收行为。命令预览也覆盖这一路径，使所有新批次都必须先审阅命令。

## 6. 前端交互

成员批量开通表每行增加账号方式：`创建新账号` / `纳管已有账号`。纳管模式使用可搜索的已有账号选择器，并显示 UID、home、主组、锁定状态和已有公钥数量；不显示数据目录和权限模板编辑。

预检完成后在成员页直接显示确认面板，按机器列出：

- 账号来源、用户名、home 和关键盘点值。
- 已有公钥指纹、将追加的公钥指纹、警告。
- 固定 Ansible 任务摘要。
- 可展开复制的完整等价 Shell 命令。
- 逐机预检状态和错误。

只有勾选“我已审阅以上命令”后确认按钮可用。执行记录页保留相同的命令详情和确认入口，页面刷新后仍可确认。

## 7. 测试与验收

- 模型和迁移测试证明历史授权默认为 `created`，旧账号字段可持久化。
- API 测试覆盖纳管请求、缺少盘点值、用户名冲突、旧账号无需 `data_root`、命令快照和授权序列化。
- 服务测试覆盖成功后记录平台公钥，以及旧账号撤销快照只使用已记录公钥。
- Ansible 语法测试覆盖创建/纳管/撤销分支。
- 前端测试覆盖加载已有账号、提交纳管行、预检命令显示、命令审阅门禁和执行记录持久确认。
- 全量 pytest、Vitest、TypeScript build 和 Alembic upgrade 必须通过。
